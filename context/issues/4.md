## Цель

Создать реальную админку Storm внутри CL-Gnosis. Приложение живёт в собственном каталоге `apps/storm-admin/`. Go/Elixir/Prolog остаются внешней системой, к которой админка подключится позднее.

## Принятые решения

- Frontend строится на семантическом HTML, vanilla JS и C/WASM без frontend-фреймворка.
- WASM-арена является авторитетным состоянием; JS читает память и проецирует состояние в DOM.
- Используются три логические области линейной памяти: арена 16-байтовых узлов, объектный пул и dirty-массив.
- Значимый DOM-элемент связывается с узлом через стабильный `data-node-id`.
- Смена активного корня означает замену шаблона; изменение атома означает точечный DOM patch через dirty-ID.
- Шаблоны монтируются в постоянную точку `#workspace` внутри оболочки `#app`.
- Для оформления локально vendored Pico CSS `2.1.1`, classless, неминифицированный. Оригинальная MIT-лицензия хранится рядом; наши переопределения живут отдельно в `styles/storm-admin.css`.
- Pico используется как базовый семантический слой. Специфический вид списков и экранов задаём своими стилями по мере появления интерфейса.
- WebSocket подключается позже как источник мутаций арены и не должен менять сценарий рендера.

## Текущий результат

- Создан и собирается `apps/storm-admin/`.
- WASM экспортирует базы арены, object pool и dirty-массива.
- Добавлен шаблон главной страницы со списком топологий.
- В арене материализованы три статические топологии: `Core M`, `Test a`, `Test b`.
- JS читает строковые атомы и object pool напрямую из `WebAssembly.Memory`.
- Клон шаблона заполняется тремя `<li>` вне живого DOM и монтируется в `#workspace`.
- Сборочная и браузерная проверки проходят.

## Ближайший маршрут

1. Оставить один шаблон страницы списка топологий.
2. Превратить названия топологий в выбираемые ссылки.
3. Передавать выбранный `TopologyID` в WASM.
4. Сохранять выбранную топологию в арене.
5. Переключать активный корень со списка на детали.
6. Использовать один общий шаблон деталей для всех топологий.
7. Подставлять данные выбранной топологии через arena/object pool.
8. Позже подключить WebSocket: событие → WASM mutation → dirty nodes → точечный DOM patch.

## Инварианты

- Авторитетное прикладное состояние не хранится в JS.
- JS не изменяет payload узлов напрямую.
- Поиск DOM-элементов ограничивается управляемым scope.
- Эксперименты в `src/experiments/` сохраняются как независимые полигоны.
- Не вводим абстракции и UI-слои до появления реальной повторяемой необходимости.
