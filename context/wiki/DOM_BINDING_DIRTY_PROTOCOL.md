# DOM binding and dirty update protocol

## Назначение

Протокол связывает узлы WASM-арены с реальными DOM-элементами и переносит локальные изменения из арены в DOM без повторного обхода или полной перерисовки страницы.

Два режима обновления разделены:

```text
смена активного корня → замена шаблона
изменение атома       → точечный DOM patch
```

Эта страница описывает второй режим.

## Идентификатор связи

Каждый управляемый DOM-элемент получает `data-node-id`. Его числовое значение совпадает с индексом соответствующего узла:

```text
data-node-id="1" ↔ arena[1]
data-node-id="2" ↔ arena[2]
```

Обычный HTML-атрибут `id` остаётся независимым идентификатором DOM. Связь с ареной задаёт только `data-node-id`.

Все элементы ищутся только внутри управляемого корня `#app`.

## Реестр DOM-ссылок

`nodeToDomMap` хранит отображение:

```text
node_id → DOM-элемент
```

Реестр создаётся один раз при подключении элементов текущей страницы. Он позволяет перейти от dirty-ID прямо к нужному элементу без повторного поиска по документу.

При удалении страницы её связи должны быть удалены. При создании новой страницы её элементы регистрируются заново.

## Раскладка WASM-памяти

Эксперимент использует три логические области одной `WebAssembly.Memory`:

1. `arena` — массив фиксированных узлов.
2. `object_pool` — байты строк и других объектов переменного размера.
3. `dirty_nodes` — массив ID изменённых узлов.

`dirty_count` хранит число действительных записей в `dirty_nodes`.

Текущий узел состоит из четырёх 32-битных слов и занимает 16 байт:

```text
+0   tag
+4   left
+8   right
+12  payload
```

Адрес узла вычисляется так:

```text
arena_base + node_id × 16
```

JS получает базы областей через экспортированные WASM-функции:

```text
get_arena_base()
get_object_pool_ptr()
get_dirty_nodes_ptr()
```

## Представления памяти в JS

Для каждой области используется подходящее представление над тем же `wasm.memory.buffer`:

```text
arena        → DataView
object_pool  → Uint8Array
dirty_nodes  → Uint32Array
```

Представления не копируют данные. Они читают линейную память WASM напрямую.

## Чтение значений

### Числовой атом

Значение находится непосредственно в `payload` узла по смещению `+12`.

```text
node_id
→ arena_base + node_id × 16
→ payload
→ DOM textContent
```

### Строковый атом

`payload` содержит смещение объекта относительно начала `object_pool`.

Текущее строковое представление имеет префикс длины:

```text
[byte_length][UTF-8 bytes...]
```

Порядок чтения:

```text
node.payload
→ object_pool_ptr + payload
→ прочитать byte_length
→ создать Uint8Array для UTF-8-байтов
→ TextDecoder
→ DOM textContent
```

Длина означает число UTF-8-байтов, а не число JavaScript-символов.

## Первичная отрисовка

После инициализации:

1. Найти `#app`.
2. Найти внутри него элементы с известными `data-node-id`.
3. Заполнить `nodeToDomMap`.
4. Для каждого связанного узла прочитать `tag` и `payload`.
5. Прочитать число напрямую либо декодировать строку из `object_pool`.
6. Записать значение в связанный DOM-элемент.

Первичная отрисовка не использует dirty-список: она материализует исходное состояние арены.

## Локальная мутация

WASM является единственным автором изменений арены. JS не записывает `payload` через смещение.

Функция мутации выполняет две операции:

```text
изменить arena[node_id]
mark_dirty(node_id)
```

Это сохраняет единый инвариант: каждое наблюдаемое изменение узла сопровождается его ID в dirty-списке.

## Flush dirty-узлов

После возврата из функции мутации JS:

1. Получает `dirty_count`.
2. Создаёт `Uint32Array` от `dirty_nodes_ptr` длиной `dirty_count`.
3. Для каждого `node_id` находит элемент в `nodeToDomMap`.
4. Читает актуальное значение соответствующего узла.
5. Обновляет только найденный DOM-элемент.
6. После успешной обработки вызывает `clean_dirty_nodes()`.

Полный цикл:

```text
DOM event
→ WASM mutation
→ mark_dirty(node_id)
→ get_dirty_count()
→ dirty_nodes
→ nodeToDomMap[node_id]
→ прочитать новое значение
→ точечный DOM patch
→ clean_dirty_nodes()
```

## Инварианты

- `node_id` стабилен и одинаков в HTML, арене и dirty-списке.
- Поиск элементов ограничен корнем `#app`.
- WASM владеет состоянием; JS только читает его и обновляет DOM.
- Любая наблюдаемая мутация вызывает `mark_dirty`.
- Dirty-список очищается только после успешного DOM flush.
- Локальная мутация не пересоздаёт шаблон.
- Смена корня не обрабатывается как локальный dirty patch: она заменяет шаблон и перестраивает DOM-связи.

## Подтверждённый минимальный пример

В эксперименте `src/experiments/dom-bindings`:

- `arena[1]` — строковый атом со значением `hi` в `object_pool`;
- `arena[2]` — числовой атом со стартовым значением `33`;
- клик вызывает WASM-функцию `increment_node(2)`;
- WASM меняет значение на `34` и добавляет ID `2` в dirty-список;
- JS находит кнопку через `nodeToDomMap[2]` и обновляет только её текст;
- `clean_dirty_nodes()` завершает цикл.
