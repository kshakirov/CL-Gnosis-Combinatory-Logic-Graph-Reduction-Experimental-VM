# 3. Управление вычислениями: Бесстековый спуск и инверсия указателей

## Статус
Предложено (Proposed)

## Контекст
Для поиска активного комбинатора (redex), готового к переписыванию, движок ВМ должен спуститься по левым ветвям бинарного графа аппликаций (`left -> left -> left`). В традиционных архитектурах для хранения обратного пути к корню используется системный стек вызовов. 

Однако при работе с глубокой рекурсией (например, разворачиваемой комбинатором `Y`) использование внешнего стека неизбежно ведет к его переполнению (Stack Overflow) и привязывает нас к линейной фон-неймановской модели памяти. Нам нужен способ осуществлять навигацию по графу, используя только саму структуру графа.

## Решение
Мы полностью отказываемся от использования вспомогательного стека адресов для управления рекурсией. Поиск активной молекулы графа будет осуществляться методом **Spine Crawl** с использованием **Алгоритма инверсии (выворачивания) указателей** (Pointer Reversal).

1. **Динамическая нить Ариадны**: По мере того как управляющий движок спускается вглубь по левым указателям узлов, он временно перезаписывает поле `left` текущего узла, направляя его назад — на родительский узел.
2. **Подъем и восстановление**: Дойдя до стабильного базового комбинатора и проверив его валентность на мета-уровне, движок выполняет топологическую редукцию, а затем поднимается обратно к корню по вывернутым указателям, восстанавливая исходную геометрию памяти на лету.

## Последствия
* **Положительные**:
  * Потребление памяти для управления потоком вычислений падает до абсолютного нуля `O(1)`. Программа вычисляется «внутри» самой себя.
  * Теоретическая бесконечная рекурсия для комбинатора `Y` становится аппаратно безопасной.
* **Отрицательные**:
  * Временная деструктуризация графа в процессе спуска делает невозможным параллельный обход одних и тех же узлов другими потоками без блокировок. Сложнее организовать многопоточность.
